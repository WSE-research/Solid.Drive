= useOneDriveActions

Action handlers for the OneDrive shell that depend on the current selection.
Owns the toast wiring and the delete confirmation prompts so `OneDriveLayout` is reduced to composition.

== Arguments

[cols="1,3", options="header"]
|===
| Field | Description

| `selected` | Current selection from link:../useSelectedResource/[useSelectedResource]
| `catalogByContainer` | `Map<containerUri, CatalogEntry>` from `OneDriveLayout`
| `catalogUri` | URI of the owner's DCAT catalog. Needed for catalog cleanup on delete.
| `solidFetch` | Authenticated Solid fetch
| `onAfterDelete` | Fired after a successful delete so the shell can clear the selection and close the panel
| `storageRootUri` | Pod storage root. Required for soft delete — the trash lives here, not under the app container.
| `entry` | The selection's catalog-row payload (`OneDriveLayout`'s `sharedEntry` memo), passed through to `softDeleteFile`. Only files need this; a folder's soft delete reads its own catalog subtree directly, so it soft-deletes without it.
| `ownerWebId` | WebID used as the trash catalog entry's publisher.
|===

== Returns

[cols="1,3", options="header"]
|===
| Field | Description

| `handleCopyLink` | Copies the selection URI to the clipboard and toasts the result
| `handleDownload` | Downloads the file binary, toasts on failure
| `handleDelete` | Moves the selection to the Recycle bin when its required data is resolved (a file needs `storageRootUri`/`entry`/`catalogUri`/`ownerWebId`; a folder needs the same set minus `entry`); hard-deletes otherwise
|===

`handleDelete` picks soft-delete or hard-delete, then hands the actual run to link:../../../file-explorer/hooks/useGuardedSoftDelete/[useGuardedSoftDelete], which owns the re-entrancy lock, the confirm dialog, and the toast. `FileCard` uses the same hook for its own delete actions. When a folder falls back to a hard delete, its own URI also stands in for `metadataUri`, since that's how a folder is keyed in the catalog (see `appendFolderToCatalog`).

The only way to permanently delete without going through the Recycle bin first is the purge action inside the bin itself (see link:../../../file-explorer/hooks/useTrashEntries/[useTrashEntries]). `SelectionActions` in My Files only offers one delete action, and it lands in the Recycle bin whenever soft delete's prerequisites are met.
