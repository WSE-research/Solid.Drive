= useCatalog

Loads the list of files and folders a user has stored, from a catalog file kept in their Pod.

== Behaviour

. Fetches the catalog and reads it into a list of entries.
. Splits that list into files and folders, so folders never get mistaken for files anywhere else in the app (search, upload duplicate checks, the Recent list, and so on).
. Keeps a shared cache, so if another part of the app already loaded the same catalog a moment ago, this just reuses that result instead of fetching again.
. Reloads automatically whenever the catalog address changes, and cleans up safely if the component using it disappears while a fetch is still running.
. If loading fails, everything resets to empty and the failure is reported separately so the caller can show an error message.

== Parameters

[cols="1,1,3", options="header"]
|===
| Parameter | Type | Description

| `catalogUri` | `string \| undefined` | Address of the catalog to load. Leave it undefined to skip loading entirely.
|===

== Returns

[cols="1,1,3", options="header"]
|===
| Key | Type | Description

| `entries`       | `CatalogEntry[]`      | The files in the catalog
| `containerUris` | `Set<string>`         | Each file's own folder address, used to tell a real folder apart from a file's storage folder
| `folderTitles`  | `Map<string, string>` | Each folder's address mapped to the name the user gave it when creating it. Derived from `folderIndex`
| `folderIndex`   | `FolderIndex`         | Every folder in the catalog, keyed by address, with its own parent link. Lets a breadcrumb trail be built without extra fetches
| `loading`       | `boolean`             | True while the catalog is being loaded
| `error`         | `Error \| null`       | Set if loading failed, otherwise null
|===
