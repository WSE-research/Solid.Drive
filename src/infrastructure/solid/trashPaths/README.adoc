= trashPaths

URI scheme for the trash: `trash/catalog.ttl` at the pod storage root, and `trash/<id>/` per soft-deleted item. A trashed file holds `payload`, `index.ttl`, `acl-snapshot.ttl`, and `tombstone.ttl`; a trashed folder holds a `payload/` container mirroring its original subtree, plus `catalog-snapshot.ttl` in place of `index.ttl`. It lives at the storage root, not the app container, so it's a pod-wide recycle bin, not scoped to this one app.

The payload is always named `payload` (or, for a folder, held under `payload/`), regardless of the original filename. That sidesteps filename edge cases (spaces, accents, percent-encoding) for what's purely internal bookkeeping; the real name lives on the tombstone (`originalBinaryName`) and is restored on undelete. Trash item ids are plain unique strings supplied by the caller, so this module has no side effects and stays deterministic in tests.

The container is `trash/`, not `.trash/`: a leading dot reads as hidden to most generic Solid pod browsers and gets filtered from their listing by default. It's hidden from this app's own My Files view at the application level instead (`isVisibleContainer` in link:../../../features/file-explorer/services/fileFilter/[fileFilter]), not by naming convention. Search stays clean too, since trashed items live in their own catalog that `useFileSearch` never reads from.
