= tombstone

Records where a soft-deleted file or folder came from, when it was deleted, and when it expires. There is one tombstone per trashed item, stored as `tombstone.ttl` inside its trash item container (see link:../trashPaths/[trashPaths]).

The tombstone uses standard vocabularies so other Solid applications can read it. Activity Streams 2.0 gives the type `as:Tombstone`, the deletion time `as:deleted`, and the item's former class `as:formerType`. PROV-O types the same node as a `prov:Entity` and repeats the deletion time as `prov:invalidatedAtTime`, which the thesis's tombstone shape requires. Dublin Core gives what another application needs for a restore: the name (`dcterms:title`), the former location (`dcterms:source`), the retention deadline (`dcterms:valid`), and links to the preserved copies (`dcterms:hasPart`). The project's own `trash:` terms hold the extra details this app needs to put an item back exactly, such as its catalog entry and whether an access-control snapshot exists. Restore reads the `trash:` terms, and tombstones written before the Dublin Core terms were added carry only those.

`parseTombstone` returns `null` when any required field is missing, so a corrupt or truncated tombstone is never restored from.
