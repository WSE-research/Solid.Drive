= e2e step screenshots

Picture-by-picture documentation of the typical user workflows, captured
straight from the end-to-end suite (issue #57 → #68).

Each end-to-end test writes its screenshots into its own folder here:

----
e2e/screenshots/<test-name>/01-landing-page.png
e2e/screenshots/<test-name>/02-identity-provider-login.png
e2e/screenshots/<test-name>/03-app-loaded.png
...
----

`<test-name>` is the spec file plus the test title, slugified. Files are
numbered in the order the steps run.

== How they are produced

Capture is opt-in, driven by the shared helpers in `e2e/helpers/`:

* `e2e/helpers/screenshots.ts` owns the capture: `shot(page, label)`
  drops a numbered screenshot into the active test's folder, and the
  `documentationScreenshots` auto fixture in `e2e/helpers/fixtures.ts`
  opens a fresh folder before each test.
* The UI helpers (`login-ui.ts`, `onedrive.ts`, `ui-actions.ts`) call
  `shot()` after each meaningful action, so most tests are documented
  with no per-test wiring.

Screenshots are captured only when `E2E_SCREENSHOTS=1` is set, so a
normal `npm run test:e2e` stays fast and writes nothing. `CI` has no
say: capture is off there too.

[cols="1,3", options="header"]
|===
| Condition | Capture

| `E2E_SCREENSHOTS=1` | on
| otherwise (including CI) | off
|===

To regenerate them:

[source,bash]
----
# clear folders of renamed/deleted tests, then recapture
rm -rf e2e/screenshots/*/
E2E_SCREENSHOTS=1 npm run test:e2e

# -f: the per-test folders are gitignored; -A: stage the deletions too
git add -A -f e2e/screenshots
----

The per-test folders are gitignored (`e2e/screenshots/*/`) so a plain
local run never dirties your working tree; only this README is tracked
by hand, and refreshed screenshots are force-added deliberately.

== Not in CI

Capturing screenshots roughly doubled the `Playwright Tests` job and
cost a lot of GitHub Actions minutes for output that only changes when
the UI does. The workflow therefore runs the suite with capture off and
never touches this folder.

Refreshing it is a local pre-commit step instead — see the
`e2e-screenshots` skill in `.claude/skills/e2e-screenshots/SKILL.md`,
which carries the full procedure and the gotchas.
